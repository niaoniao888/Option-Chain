# 统一界面规范：BTC 默认基准

## 约定与边界

BTC 是默认视觉和通用交互基准。新增市场与 BTC 并列，使用同一套界面风格；特色业务内容可以不同。本约定不改变启动地址、模块排序、上次页面记忆、行情刷新或任何市场计算口径。

默认基准是最新已验收的 BTC 通用设计，不是把 BTC 的全部代码复制到其他模块。用户修改 BTC 通用风格时，应修改共享规则并同步核验现有模块；只影响 BTC 业务的修改保持在 BTC 内。

## 为什么曾经出现差异

BTC 与美股原先是独立页面，拥有不同 HTML 结构、选择器和 CSS。整合后加载共享 market-shell.css，但旧模块规则仍存在，优先级较高的选择器、媒体查询或子元素样式会继续生效。排序重绘还可能覆盖 HTML 中的响应式文案。仅验证数据和逻辑的测试无法保证最终字体、按钮尺寸和布局相同。

当前共享层已统一主要样式，但仍含兼容现有两种 DOM 的选择器，尚不是完整的通用组件库，也尚无覆盖所有视觉属性的自动浏览器门禁。后续按变更范围逐步提取，避免一次性重写成熟的市场逻辑。

## 代码责任

- `web/shared/market-shell.css`：共用主题、字体、导航、按钮、卡片、表格和响应式规范的维护入口。
- `web/shared/period-return.js` / `.css`：现有 BTC 单期收益格式。美股有自己的展示逻辑；只有语义一致并完成验证后才可合并，不能为了外观统一改变业务含义。
- `web/desktop/`、`web/mobile/`：BTC 页面与现有兼容样式。
- `web/us-equities/` 和未来市场目录：市场数据、特色结构和必要的局部布局。

新模块应复用共享规则和相同的通用控件结构。现有共享 CSS 中含市场专用选择器，不能假定仅引入文件就会自动生效：新增选择器/结构须先完成代表页面的浏览器验证。若基础控件尚未共享，应先从 BTC 提取一个小组件或共享 class，再供两个模块引用。不要复制整份旧 CSS 再覆盖。

现有入口先加载模块兼容 CSS，再加载共享规范。新增通用样式不能散落到模块文件；特色规则应有模块根 class 限定，避免污染其他市场。修改前后检查 computed style，优先删除或迁移重复规则，不继续叠加高优先级补丁。

## 当前验收基准（ui10）

下表为交接时的已验收数值，后续变更应同时更新共享实现和本表，不把本表当成另一套 CSS 配置。

| 共用项目 | PC | 手机（<=700 CSS px） |
| --- | --- | --- |
| 字体 | Segoe UI / Microsoft YaHei / system-ui；数字等宽特性 | 同左 |
| 标题 | 22px | 随窄屏适配，保留价格标题 |
| 主题按钮 | 34×28px，太阳/月亮图标 | 34×30px |
| 模块按钮 | 20px，圆角9px，选中蓝底白字 | 14px、高32px、圆角8px |
| Call/Put | 按钮高44px、字18px，组宽240px | 高38px，组宽136px |
| 期限按钮 | 高44px、字16px，不加粗 | 高38px，自适应字号 |
| 内容框 | 圆角14px | 圆角11px |
| 期权链 | 总宽1200px；普通数字不加粗 | 保留横向查看与行权价定位 |
| 价格年化 | 725px；五列150/175/130/120/150px | 容器内自适应，字号11–12px |
| 年化排行 | 10条/页、单列排序；页码34×34px，箭头< > | 全部业务列保留，字号11–12px |

颜色统一引用共享主题变量。上涨红、下跌绿；不能把空值当0。日期使用 YYYY-MM-DD；手机窄列可将年份与月日分两行。PC 列名为“单期收益率”、手机为“单期收益”；状态使用“校对状态”。倒计时等动态内容不应导致容器跳动。

## 允许保留的特色

例如美股有自选股票、开休市状态、额外的剩余时间列和参考行情标识；BTC 报价显示整数，美股保留两位小数。数据源、交易日历、结算窗口、股息、乘数、概率参数与年化基数都属于业务规则，不能继承 BTC 后不经核实地使用。

新增特色应在对应模块说明记录：为何需要、影响哪些字段/控件、是否影响两端布局、如何验证。特色仅限其作用范围，通用按钮字号和主题仍遵守共享规范。

## 新模块和通用样式验收

1. 先完成一个真实代表页面，核对共享组件，样本通过后扩展其余视图。
2. 同宽度、同主题、同类控件对照 BTC；读取浏览器最终字号、字重、宽高、内边距、圆角和颜色，不仅比较 CSS 源文本。
3. PC 检查正常宽度、窄窗口及150%缩放；手机检查320、390、430px。价格年化/排行不通过隐藏内容消除横滚；期权链按设计允许滚动。确保所有列和长值可读。
4. 检查深浅主题、选中/未选中/禁用状态、空值、错误状态和菜单展开；排序重绘、行情刷新后仍保持字体、文案及选择。
5. 检查分页、单列排序、股票切换、页面记忆、复制保护及固定表头；同步运行相关 Python/Node 测试。
6. 保存浏览器验收记录，写明未测试的实体设备和特色差异。新增自动视觉检查应复用这一对照方法；本规范本身不是已经实现的自动阻止机制。
