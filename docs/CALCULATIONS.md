# 计算契约与展示规则

权威实现：`src/options_panel/domain/calculations.py`；冻结与异常处理：`runtime/snapshot.py`；验收用例：`tests/test_server.py`。此文记录已实现口径，不改变原看板算法。

## 同一批次的输入

- `S`：Binance BTCUSDT 指数原始数值，不用页面取整值，也不换成另一交易所现货价。
- `K`：行权价；`Bid`：有效买一报价；`expiry_ms`：UTC Unix 毫秒到期时间。
- `t`：该成功批次最终读取的交易所服务器时间。`T = (expiry_ms - t) / 1000 / 31,536,000`。
- 显示剩余整数天/小时，不参与计算。不能先把剩余时间取整为 7 天再计算。
- 毫秒是上游协议的时间单位，不代表每毫秒刷新。两次成功行情之间收益指标保持不变。

## 时间价值、单期收益与年化

```text
Call 内在价值 = max(S - K, 0)
Put  内在价值 = max(K - S, 0)
TV = Bid - 内在价值

Covered Call 比较基准 B = S
Sell Put     比较基准 B = K
单期收益率(%) = TV / B × 100
年化(%) = 单期收益率(%) / T
```

`B` 是看板的比较基准，不是账户实际保证金或券商资金占用。合约单位会校验；权利金和分母在同单位比较时倍数相消。买价不保证成交，指标不含税费、滑点、现货持仓盈亏等。

Covered Call 的单期收益列第一行展示 `(K/S - 1) × 100%`，红色表示行权价高于现价，绿色表示低于；第二行是上述 TV 单期收益。**两行不相加，也不代表实际已实现收益。** Sell Put 只显示 TV 单期收益，不显示行权价距现价一行；两种方向的后台计算公式均不变。

样例：Put 的 S=90,000，K=100,000，Bid=10,500，剩余精确 30 天：内在价值 10,000，TV=500，单期 0.5%，单利年化约 6.0833%。这只是数学样例。

## 不可用及非正时间价值

- OI=0、买价无效、指数无效或已到期，不展示正常收益率；空值使用 JSON `null`，页面统一 `—`。
- TV≤0 时保留 `time_value` 和状态，但正常 `annualized_pct` / `period_return_pct` 为空，显示 `Bid < 内在价值`。这一既有简写也涵盖 TV=0；它不是零收益的声明。
- PC 可显示 TV 和同轮 Mark 的参考年化；手机仅显示该提示。Mark 不是可成交的替代买价。
- 价格年化中的非正 TV 合约及相应不可选价格按原规则过滤；期权链仍能提示异常。

## 行权概率

```text
d2 = [ln(S/K) + (r - σ²/2)T] / (σ√T)
Call = N(d2) × 100%
Put  = N(-d2) × 100%
```

`σ` 为该合约 `markIV`，`r` 为 `riskFreeInterest`（按连续复利解释），持有收益率 q=0；N 是标准正态累计分布函数。使用同轮指数和计算时间。

这是模型下到期实值的风险中性概率，不是实际行权保证、触及概率或亏损概率。有效零/负利率允许；σ 缺失、非正、非有限，或 r 非有限/缺失时不可用。距到期不超过 30 分钟展示“结算中”，到期后停止。此版没有建立结算窗口的高频均价模型。

显示一位小数，极小/极大概率用 `<0.1%` / `>99.9%`。`delta` 与 `mark_price` 仅供核验，不能直接替代概率。

## 失败与时间

主行情失败保留上一批次的年化、概率和计算时间，不随墙上时钟重新计算。Mark 单独失败时，本轮主行情仍可更新，概率留空。UTC 时间传输；前端以 `Asia/Shanghai` 展示。`last_trade_time_ms` 是最后成交时间，不能被当作买卖盘更新时间。
